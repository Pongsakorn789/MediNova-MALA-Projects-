# MALA AI Logic (Rule-Based)

## สรุป

ระบบ MALA ในเวอร์ชันปัจจุบัน **ไม่ได้ใช้โมเดล AI ที่ผ่านการฝึก (trained model)** และไม่ได้เชื่อมต่อ Hugging Face เพื่อสร้างผลคัดกรองหรือคำแนะนำ ระบบใช้กฎและเงื่อนไขที่เขียนไว้ในโค้ด (rule-based) ผลลัพธ์จึงตรวจสอบย้อนกลับได้ตามข้อมูลและเงื่อนไขที่กำหนด

ชื่อ API `/api/evaluate-mala-ai` มีคำว่า `ai` แต่การทำงานจริงเป็น rule-based โดย API ส่ง `guidanceType: "rule-based"` กลับมา

## ส่วนการคัดกรอง

### Part 1: ประเมินขนาดยา Metformin ตาม eGFR

โค้ด `src/utils/metforminGuideline.ts` ใช้เกณฑ์ดังนี้:

| เงื่อนไข | ผลตามกฎในระบบ |
|---|---|
| eGFR < 30 | สถานะ contraindicated; ระบุให้หยุด Metformin และแจ้งแพทย์ผู้รับผิดชอบโดยเร็ว ระบบไม่ได้สั่งหยุดยาแทนแพทย์ |
| eGFR 30–44 และขนาดยา ≤ 1,000 มก./วัน | ขนาดยาอยู่ในเกณฑ์ |
| eGFR 30–44 และขนาดยา > 1,000 มก./วัน | ให้แพทย์ทบทวนขนาดยา |
| eGFR ≥ 45 และขนาดยา ≤ 2,000 มก./วัน | ขนาดยาอยู่ในเกณฑ์ |
| eGFR ≥ 45 และขนาดยา > 2,000 มก./วัน | ให้แพทย์ทบทวนขนาดยา |
| อ่านขนาดยาไม่ได้ | ให้ตรวจสอบขนาดยาปัจจุบัน |

### Part 2: คำนวณคะแนนความเสี่ยง MALA

โค้ด `src/utils/riskEngine.ts` รวมคะแนนตามเงื่อนไขนี้:

| ปัจจัย | คะแนน |
|---|---:|
| eGFR < 60 | 1 |
| BMI > 0 และ BMI < 23 | 2 |
| ดื่มหนักตามเกณฑ์ที่บันทึก (ดื่มหนักเป็นครั้งคราว หรือปริมาณสูงต่อสัปดาห์) | 2 |

คะแนนรวมตั้งแต่ 2 ขึ้นไปจัดเป็นระดับ `Yellow` และต่ำกว่า 2 เป็น `Green` ตามการกำหนดในโค้ดปัจจุบัน

### Part 3–4: ปัจจัยกระตุ้นและคำแนะนำ

Backend ใน `backend/main.py` ตรวจข้อมูลที่ได้รับทีละเงื่อนไข แล้วรวมคำแนะนำที่ตรงกับข้อมูล:

- eGFR < 45: แนะนำให้แพทย์ทบทวนความเหมาะสมและขนาดยา Metformin
- ดื่มหนักหรือดื่มเรื้อรัง: แนะนำหลีกเลี่ยงการดื่มหนักและปรึกษาบุคลากรสุขภาพ
- อาเจียน/ท้องเสีย หรืออดอาหาร: แนะนำติดต่อ รพ.สต./แพทย์เพื่อขอคำแนะนำเรื่องยาระหว่างวันป่วย
- ใช้ยาแก้ปวด/ยาแก้อักเสบ/ยาชุด: แนะนำปรึกษาแพทย์หรือเภสัชกรพร้อมรายการยา
- ใช้สมุนไพรหรืออาหารเสริม: แนะนำแจ้งบุคลากรสุขภาพและให้ตรวจสอบผลิตภัณฑ์
- ถ้าไม่มีเงื่อนไขข้างต้น: ส่งคำแนะนำทั่วไปตามแผนแพทย์และให้แจ้งบุคลากรเมื่อเจ็บป่วย

API ส่งกลับข้อความคำแนะนำที่จับคู่กับเงื่อนไข ไม่ได้สร้างข้อความใหม่ด้วยโมเดลภาษา

## ข้อมูลที่ส่งเข้า API

จากหน้า `Step6Result` เว็บส่ง JSON ต่อไปนี้ไปยัง `POST /api/evaluate-mala-ai`:

| ฟิลด์ | ความหมาย |
|---|---|
| `age` | อายุ (ปี) |
| `egfr` | ค่า eGFR |
| `metforminDose` | ขนาดยา Metformin (มก./วัน) |
| `hasBingeDrinking` | มีประวัติดื่มหนักเป็นครั้งคราวหรือไม่ |
| `hasChronicAlcohol` | มีการดื่มแอลกอฮอล์ปริมาณสูงต่อสัปดาห์หรือไม่ |
| `hasVomitingDiarrhea` | มีอาเจียน/ท้องเสียหรือไม่ |
| `hasFasting` | มีการอดอาหาร/รับประทานได้น้อยตามคำถามคัดกรองหรือไม่ |
| `hasPainkillers` | ใช้ยาแก้ปวด/ยาแก้อักเสบ/ยาชุดหรือไม่ |
| `hasHerbsSupplements` | ใช้สมุนไพรหรืออาหารเสริมหรือไม่ |

ปัจจุบัน API รับ `age` และ `metforminDose` แต่กฎสร้างคำแนะนำใน backend ไม่ได้นำสองค่านี้ไปคำนวณ ส่วน eGFR, ประวัติแอลกอฮอล์, อาการ/การอดอาหาร, ยาแก้ปวด และสมุนไพร ใช้เลือกข้อความคำแนะนำ

## ข้อจำกัดและการตีความ

- คะแนนและช่วงขนาดยาเป็นกฎที่กำหนดไว้ในโค้ด โดยอ้างอิงเกณฑ์ที่ใช้ในโครงการ ต้องให้ผู้รับผิดชอบทางคลินิกตรวจสอบก่อนใช้ดูแลผู้ป่วยจริง
- ผลลัพธ์เป็นเครื่องมือช่วยคัดกรองและให้ข้อมูล ไม่ใช่การวินิจฉัยหรือคำสั่งการรักษาแทนแพทย์
- คำว่า “AI” ในชื่อ endpoint เป็นชื่อเดิม ไม่ได้หมายความว่ามีโมเดล AI ทำงานอยู่
- การเปลี่ยนเกณฑ์ต้องแก้และทบทวนโค้ดที่เกี่ยวข้อง ได้แก่ `src/utils/metforminGuideline.ts`, `src/utils/riskEngine.ts` และ `backend/main.py`

## AI Evidence: Where, How, Prove, Measure

ส่วนนี้ระบุหลักฐานของกลไกที่โครงการเรียกว่า AI ในเอกสารนำเสนอ แต่ใน implementation ปัจจุบันเป็น **ระบบกฎ (rule-based)** ไม่ใช่โมเดลที่ฝึกจากข้อมูล

### Where — อยู่ตรงไหนในระบบ

| ตำแหน่ง | หน้าที่ |
|---|---|
| `src/utils/metforminGuideline.ts` | Part 1 ตรวจขนาดยา Metformin เทียบกับ eGFR |
| `src/utils/riskEngine.ts` | คำนวณ BMI, คะแนน Part 2 และระดับความเสี่ยง |
| `src/modules/vhv/VhvScreen.tsx` | เรียกใช้กฎ ตรวจขนาดยาก่อน แล้วบันทึกคะแนน/ผลคัดกรอง |
| `src/modules/vhv/steps/Step6Result.tsx` | แสดงคะแนน ปัจจัยที่ได้คะแนน และคำแนะนำบนหน้าผล |
| `backend/main.py` ฟังก์ชัน `evaluate_mala` | เลือกและรวมคำแนะนำคงที่ตามข้อมูลที่ส่งเข้า API |

ไม่มีการเรียก Hugging Face, ไม่มี tokenizer/model weights, ไม่มี prompt สำหรับ LLM และไม่มีชุดข้อมูลฝึกโมเดลในเส้นทางนี้ ชื่อ endpoint `/api/evaluate-mala-ai` เป็นชื่อเดิมเท่านั้น

### How — ทำงานอย่างไร

1. เว็บรับ eGFR, ขนาดยา, น้ำหนัก/ส่วนสูง และคำตอบปัจจัยเสี่ยงจากเจ้าหน้าที่
2. Part 1 ใช้ `assessMetforminDose` ตรวจขนาดยากับ eGFR ก่อน หากไม่ผ่าน ระบบหยุดการประเมิน MALA และส่งรายการให้แพทย์ทบทวนตาม workflow
3. หาก Part 1 ผ่าน ระบบคำนวณ BMI แล้วให้คะแนน Part 2 จาก eGFR (<60 = 1), BMI (>0 และ <23 = 2), และการดื่มหนักตามเกณฑ์ (2) รวมสูงสุด 5 คะแนน; คะแนนตั้งแต่ 2 จัดเป็นกลุ่มเสี่ยง
4. Part 3–4 เป็นปัจจัยประกอบและคำแนะนำ ไม่รวมในคะแนน Part 2
5. Backend ตรวจ Boolean/ตัวเลขด้วย `if` statements แล้วคืนข้อความคำแนะนำที่เขียนตายตัว กฎที่ตรงกันหลายข้อจะได้คำแนะนำหลายข้อ ไม่มีการสุ่มหรือสร้างภาษาใหม่

### Prove — ชุดกรณีทดสอบอ้างอิง

ตารางนี้เป็น **test set ที่กำหนดเพื่อให้ตรวจซ้ำได้** โดยผลลัพธ์เป็นผลที่คาดจากการอ่านกฎใน source code ไม่ใช่ผลการรันทดสอบจริง โปรดรันและบันทึก log ก่อนนำเสนอว่าเป็นผลทดสอบ

#### ชุด Part 1–2 (Frontend)

| ID | Input | Expected result |
|---|---|---|
| F01 | eGFR 50, dose 2,000 mg/day | Part 1 ผ่าน; Part 2 ได้ 1/5 (eGFR) = ต่ำกว่าเกณฑ์เสี่ยง |
| F02 | eGFR 50, dose 2,000 mg/day, BMI 22 | Part 1 ผ่าน; Part 2 ได้ 3/5 (eGFR + BMI) = เข้าเกณฑ์เสี่ยง |
| F03 | eGFR 70, dose 1,000 mg/day, BMI 24, ดื่มหนักตามเกณฑ์ | Part 1 ผ่าน; Part 2 ได้ 2/5 = เข้าเกณฑ์เสี่ยง |
| F04 | eGFR 40, dose 1,500 mg/day | Part 1 ไม่ผ่านและให้แพทย์ทบทวน; ไม่ควรไปคำนวณ Part 2 ต่อ |
| F05 | eGFR 29, dose 500 mg/day | Part 1 เข้าเงื่อนไข eGFR <30; แจ้งแพทย์และหยุด flow คัดกรองต่อ |

#### ชุดคำแนะนำ Backend (`POST /api/evaluate-mala-ai`)

ใช้ฟิลด์ที่ไม่ได้กล่าวถึงในกรณีทดสอบเป็นค่าปกติ `false`; `age` และ `metforminDose` ใส่ค่าที่ schema ยอมรับ กรณีทดสอบตรวจข้อความ/เงื่อนไขที่ต้องมี ไม่ตรวจการจัดอันดับหรือคุณภาพภาษา

| ID | เงื่อนไขที่เปิด | Expected result |
|---|---|---|
| B01 | eGFR 60, flags ทั้งหมด false | คำแนะนำทั่วไป; `guidanceType` เป็น `rule-based` |
| B02 | eGFR 44, flags อื่น false | มีคำแนะนำให้แพทย์ทบทวน eGFR/ขนาดยา |
| B03 | `hasBingeDrinking=true` | มีคำแนะนำเรื่องหลีกเลี่ยงการดื่มหนัก |
| B04 | `hasFasting=true` | มีคำแนะนำติดต่อบุคลากรเพื่อขอคำแนะนำระหว่างวันป่วย |
| B05 | `hasPainkillers=true` | มีคำแนะนำให้ทบทวนรายการยากับแพทย์/เภสัชกร |
| B06 | `hasHerbsSupplements=true` | มีคำแนะนำให้แจ้งและตรวจสอบสมุนไพร/อาหารเสริม |
| B07 | เปิด `hasBingeDrinking`, `hasFasting`, `hasPainkillers` พร้อมกัน | ผลรวมต้องมีคำแนะนำครบทั้งสามเงื่อนไข |

#### Baseline ที่ใช้เปรียบเทียบ

Baseline ของระบบนี้คือ **ตารางกฎและผลที่คาดหมายซึ่งมนุษย์ตรวจจาก source code ได้** ไม่ใช่โมเดลรุ่นเก่าหรือการทำงานแบบไม่มี AI ที่มีผลวัดไว้ โครงการยังไม่มี benchmark dataset, model, prompt หรือผลทดลองเทียบโมเดล จึงไม่ควรอ้างว่า AI มี accuracy สูงกว่า baseline

### Measure — วัดผลอย่างไรและสถานะผล

ตัวชี้วัดที่ใช้กับ test set ด้านบนได้:

- **Rule case pass rate** = จำนวนกรณีที่ผลจริงตรงกับ expected result ÷ จำนวนกรณีที่รันทั้งหมด
- **Expected recommendation coverage** = จำนวนคำแนะนำที่คาดและพบในผลจริง ÷ จำนวนคำแนะนำที่คาดทั้งหมด
- **Unexpected recommendation count** = จำนวนคำแนะนำที่ปรากฏทั้งที่ไม่ได้เปิดเงื่อนไขนั้น
- **Part 1 routing correctness** = จำนวนกรณี F04–F05 ที่หยุด Part 2 และเข้าผลการส่งแพทย์ตามที่คาด ÷ จำนวนกรณี dose-fail ที่ทดสอบ

ข้อจำกัด: การผ่าน test set แสดงเพียงว่ากฎทำงานตรงตามข้อกำหนดที่เขียนไว้ ไม่ได้พิสูจน์ความถูกต้องทางคลินิก ประสิทธิผลในการลด MALA หรือความเหมาะสมกับผู้ป่วยทุกกลุ่ม เกณฑ์ต้องได้รับการยืนยันจากผู้เชี่ยวชาญทางคลินิกก่อนนำไปใช้จริง
